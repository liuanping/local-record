# 本地录音 · Android 版

电脑版（`../`）的手机端移植：**录音 → 离线转写（中英混说）→ 标点 → 会议纪要/问答（本地大模型）**，全程不联网。

## 交付物

| 文件 | 说明 |
|---|---|
| `dist-android/LocalRecord-android-1.7.0.apk` | **发布版（96MB，已签名）**，含 arm64-v8a 与 x86_64 |
| `dist-android/phone-files/` | 可选：想手动拷模型时用（`models/` + `llm/`）。**不必需** |

## 功能（三个页签）

| 页签 | 做什么 |
|---|---|
| **语音** | 录音 → 停录即出字（8 秒一段）→「生成会议纪要」/ 就转写提问 |
| **录音库** | 列出录音：播放、转写已有 wav |
| **文档问答** | 选图片 → 离线 OCR（与电脑版同一套 PP-OCRv6）→ 就文档内容提问 |

## 安装（装完打开就行，不用选、不用点）

1. 把 `LocalRecord-android-1.4.0.apk` 传到手机点开安装（允许"未知来源应用"）。
2. 打开 app —— **它会自己把缺的模型全部下完**（转写+标点+大模型+OCR 共约 1.75GB），
   不需要任何选择或点击；顶部状态栏显示进度与速度。
3. 下完自动就绪。断网/中断都没关系：**下次打开会从断点续下**，网络恢复也会自动继续。

### OCR 是怎么实现的（为什么不是 ML Kit）

* 用**电脑版同一套 PP-OCRv6 medium det/rec ONNX 模型**（ModelScope 上有，62MB + 76MB），
  全程离线、不依赖 Google 服务；
* 推理走自己写的 `app/src/main/cpp/ocr_jni.cpp`：**dlopen sherpa-onnx 已经带进来的
  `libonnxruntime.so`**（1.20.1），拿 ORT 的 C API 自己开 session —— 这样不会和
  `com.microsoft.onnxruntime:onnxruntime-android`（1.20.0）**两个同名 .so 打架**；
* 检测后处理（DB 算法：阈值 0.2 二值化 → 8 邻域连通域 → 平均分 ≥0.45 → unclip 1.4 外扩）
  与识别（高度 48 归一化 → CTC 贪心解码，字典 18708 字符，来自 `assets/ocr_rec_dict.txt`）
  都在 Kotlin 侧（`OcrEngine.kt`）。

**实测（模拟器，900×520 中文测试图，5 行）：**
```
本地录音测试文档
今天的会议改到下午三点，请大家准时参加。
付款方式：银行转账，30天内结清。
合同编号HT-2026-0417
联系电话13800138000
```
**5 行全部逐字正确**（含中文标点与数字），用时 7.6s（模拟器软件渲染，真机约 1~2s）。

> 踩到的坑：PP-OCRv6 的字典里有一项是**全角空格 U+3000**，手写解析时 `line.strip()`
> 会把它当空白吃掉 → 跳过该项 → **后面所有中文索引错位一位**。
> 症状极有辨识度：**数字/字母全对、汉字全错**。改用 PyYAML 正式解析（18708 项）后全部正确。
> 复现脚本：`../scripts/extract_ocr_params.py`。

要点：

* **全部走 ModelScope**（国内直连、支持 Range 续传）；ModelScope 失败才自动兜底 hf-mirror。
* **已有的文件不会重复下载**：按精确字节数判定"已完成"，所以升级 APK 后不会重下 1.6GB。
  手动导入的、以前下过的（外置目录或应用内部存储）都算已有。
* 中断（切网/退出）后下次打开**接着下**，不会从头来。
* 下完校验字节数，不符视为失败并重试。

### 备选：手动导入

把 `phone-files/` 里的 `models/` 与 `llm/` 拷到手机任意位置，点「导入模型」选中那一层目录
（按文件名递归查找：`model.int8.onnx`+`tokens.txt`→转写，`model.onnx`+`tokens.json`→标点，
`*.gguf`→大模型）。大模型也能单独点「选择大模型」选那个 `.gguf`。

## 模型与验证现状

| 项 | 模型 | 本机验证情况 |
|---|---|---|
| 转写 | Paraformer zh int8（227MB，与电脑版同一个文件） | ✅ 识别出正确文本（含标点） |
| 标点 | CT-Transformer（294MB） | ✅ 同上 |
| 大模型 | **MiniCPM5-2B Q4_K_M（1.56GB，与电脑版一致）** | ✅ 模型**加载成功**（新 llama.cpp 认 `minicpm5`）；生成质量与速度待你手机上实测 |

```
[大模型] 找到模型=MiniCPM5-2B-Q4_K_M.gguf 大小=1488MB
         加载完成 ok=true 用时=17.4s
         LlmJni: 就绪：n_ctx=4096
         LlmJni: 使用模型自带对话模板 → llama.cpp 判定为 ChatML（正确）
```

> **速度提醒**：x86_64 模拟器上 MiniCPM5-2B 生成极慢（13 分钟没跑完 700 token，约 1 token/s），
> **真机（arm64、8 核）通常快 5~15 倍**。若在你手机上仍嫌慢，下一步最好的办法是改成
> **流式输出**（边生成边显示），而不是换小模型。

    里面是
    `{%- if enable_thinking is defined and enable_thinking is true %}<think>{%- else %}<think>\n\n</think>\n\n{%- endif %}`，
    而 llama.cpp 的 C API 不传模板变量 → 走 **else 分支** → 官方"不思考"写法。
  * 因此 JNI 也改了：**模板已经放了空思考块就不再补**（原来无条件补，会出现两层空 think，反而污染）。

* **2.3.8**：**修好思维链关闭**（用户实测"20 多个字花了 32 秒"）：
  * 真凶：MiniCPM5 的思维链标记是 **`[Start thinking] … [End thinking]`**，不是 `<think>`。
    而 `llm_jni.cpp` 里的关闭逻辑一直判断 `<think>`，**从来没匹配过** → 模型每次都在先长篇推理，
    再给出答案。按实测速率（约 7 tok/s）算，32 秒 ≈ 220 token，正好是"推理 + 短答案"。

  检查缺什么，所以"下完一个后突然断网，后面几个文件瞬间全部失败，就再也不动了"。现在：
  单文件失败重试 3 轮（主源→备源→退避 2s/4s）；**断网时挂起等待，网络恢复立刻自动继续**
  （注册 `NetworkCallback`）；**回到前台也检查一次**；失败保留 `.part`，下次用 Range 从断点续；
  连续 3 轮无进展才停手，界面给出「继续下载」入口；下载期间持 wakelock 防锁屏被挂起。
  实测证据：杀进程前 `.part`=109,793,147 字节 → 重启后第一行进度 `150/217 MB`（**从 109MB 续，不是从 0**）
  → 完成时 `落地=227330205 期望=227330205`（文件完整）→ 自动接着下 asr-tokens / punct-model；
  飞行模式断开时报 `timeout` → 恢复后 `.part` 从 38MB 涨到 52MB（未归零）。

* **1.3.2**：布局 bug —— `VoiceTab` 用了 `fillMaxSize()`，把底部「生成会议纪要 / 提问」整块挤出屏幕
  （用户手机截图里只能看到部分控件）。改为：内容区 `weight(1f)` 只吃剩余空间、底部控件固定不压缩、
  根布局加 `safeDrawingPadding()` 避开状态栏（原来标题第一个字被状态栏切掉）。
  已用模拟器截图验证（见 `dist-android/layout-preview.png`）。

* **1.2.0**：manifest 漏 `INTERNET` 权限 → 首次下载直接 `Permission denied`。已补。
* **1.3.2**：下载进度文案里 `%` 紧挨全角冒号（`"…$pct%："`），被 `String.format` 当格式符
  → **首次运行必崩** `UnknownFormatConversionException`。已修（拆成两段字符串）。
* **1.3.2**：vendored llama.cpp 从 0.3.16 升到 0.3.36 才认识 MiniCPM5 的 `minicpm5`

## 技术选型说明

* **ASR**：sherpa-onnx 的 Android AAR（hf-mirror 上有镜像的 `sherpa-onnx-1.12.38.aar`）——
  不在 Maven Central，GitHub 又拿不到。ABI 齐全（arm64/armv7/x86/x86_64）。
* **大模型**：llama.cpp 源码取自 PyPI 的 `llama-cpp-python` 源码包（内含完整 `vendor/llama.cpp`），
  用 NDK r27 交叉编译（AGP 的 `externalNativeBuild` 自动完成，两个 ABI 各约 3 分钟）。
  0.3.36 那份才支持 `minicpm5`，所以手机端用的就是**电脑版同一个 MiniCPM5-2B**。
  JNI（`app/src/main/cpp/llm_jni.cpp`）只暴露 init/generateChat/free，
  提示词用 `llama_model_chat_template` 取**模型自带模板**（不硬编码 Qwen 模板），greedy 采样。
